## 1. tophub.today 研究结论

产品矩阵（导航实测）：
- 首页：源节点网格。每个节点=一个平台榜单（知乎热榜/微博热搜/百度实时热点…），
  卡片内 ranked top-N 条目 + 热度数值 + 更新时间（"8分钟前"）。财经分类下 324 个节点，分页 27 页。
- 动态 dashboard（用户参照页）：「我的订阅动态」。订阅的榜单节点有新上榜内容时按平台分组推送
  （预览样例：抖音 2 个热门事件上榜 / 微博 3 个 / 头条 2 个，每条带标题）。
  自动刷新 30s~15min 可选、动态聚合、过滤设置、管理订阅。登录墙后个性化。
- 追踪 alerts：自定义关键词追踪器（兴趣追踪机器人）。
- 榜中榜 hot：跨平台同时上榜的条目（交叉热度）。
- 话题聚合 topics：跨平台同话题聚类（≈我们的 events）。
- 热点日历 calendar：事件时间线。
- 晚报/早报 daily（idaily.today）：「AI 总结全网 10000+ 热榜」的 AI 摘要 digest。
- 分类体系：综合/科技/娱乐/社区/购物/财经/开发/简报/AI + 报刊/设计/校务/政务/专栏/苹果/公众号/自定义分组。
- 交互细节：夜间模式、键盘 ←→ 翻页、批量订阅本页节点、节点级「热门|最新」排序切换。

核心范式总结：**分类 → 源节点 → ranked 条目 + 热度 + 新鲜度**，个性化层=订阅/追踪/过滤，
知识层=AI 晚报摘要 + 话题聚合。用户诉求映射：
- 「分类目概括各版本(源)热点文章内容」→ 分类区 + 每类聚合各源热点（我们按事件归并呈现，优于纯标题列表）
- 「按我兴趣再做进一步深挖和呈现」→ 兴趣深挖区（持仓/watchlist 驱动，增强卡）
- 「投喂的知识更丰富一些」→ 知识增强层（类目导读 + 全文深读 + 背景扩展，见 §3）

## 2. 我方数据资产盘点（实测）

- 91 个 RSS 源，7 类目；全库 ~12 万篇，72h 窗口 ~7.4k 篇。
- articles.summary 平均 312 字符（11.5 万篇有摘要）= 主语料；content 全文基本为空
  → 深读需按需抓全文（Jina read_article，trendradar MCP 已有该工具）。
- events 5897 active；topic 分布：财经 2290 / 科技 1191 / 综合 857 / 投资 656 / 足球 418 / AI 309 / 游戏 176。
- velocity_signals（表+JSON， hourly :20 更新）：932 条热榜信号，字段
  platform/title/best_rank/latest_rank/rank_delta/crawl_count/is_new/velocity
  → 这就是我们的「榜中榜」数据源（toutiao/weibo/baidu 等平台）。
- event_facts：143 条已核验 claim（含数字核验标记）→ 可复用为知识底料。
- interest_profile 15 键（A股持仓 7 canonical + 美股 FITB/FAST/HBAN + NVIDIA + topic 4）；
  watchlist 19 条 7 组；topic_burst（科技 +0.5 至 11-23）。
- cards JSON：四段卡（事实/影响/分歧/下一步）qwen4-max 合成，数字核验 10/10。
- 发布链：staging news-web/ → /var/www/news/（nginx basic auth），单文件静态 HTML，无构建步骤。
- 约束：index.html 由 build_index_html() 每次 brief/dive 自动重建，手改会被覆盖 → 定制必须改生成代码。

## 3. 提案：门户骨架（六区）+ 知识增强三档

### 3.1 页面骨架（单文件静态 HTML + 原生 JS，移动优先）

A. 顶栏：日期 + 版次（晨/晚）+ 数据截至时间 + 源覆盖徽章（85/91）+ 搜索框 + 夜间模式。
B. 今日总览：AI 跨类目主线导读 300-500 字 + TOP3-5 头条卡（四段卡摘要态）。
C. 分类热点（核心区，tophub 式）：8 类目 tab/锚点；每类：
   - 类目导读 100-200 字（AI：今天这类发生了什么、主线是什么）
   - 3-5 张事件卡：卡面=标题+一句话事实+热度条(salience 归一)+N独立源+实体 chips+热榜徽章(若上榜)
   - 展开=四段卡全文 + 成员文章列表（源名+时间+链接，跨语归并后含全部成员）+ merged_from 标注
D. 兴趣深挖区（个性化，知识增强主战场）：
   - 持仓雷达：FITB/FAST/HBAN + A股 7 名，逐实体列今日相关事件（无则诚实显示「今日无新增」）
   - 增强六段卡：事实/背景/影响/数据/分歧/下一步；「背景」段显式标注
     「模型背景知识，非当日报道」；数字仍只允许来自语料（核验纪律不放松）
   - 核心文章全文深读：对兴趣命中事件抓 1-2 篇全文（Jina）扩充语料后再合成
   - watchlist 关键词命中流（19 条 7 组）
E. 热榜交叉验证（榜中榜式）：velocity_signals × events 匹配 →
   「我们的哪些事件正在哪些平台热榜、第几名、排名变化」；同时列 RSS 未覆盖的纯热榜条目（盲区提醒）。
F. 归档与工具：日期归档（带类目计数元数据）、A/B 评测入口、说明页脚。

### 3.2 知识增强三档（成本阶梯，qwen4-max 实测单价外推）

- L1 现状：TOP10 四段卡，~18k tokens/日。
- L2 类目版：8 类 × 3 卡 + 8 类目导读 + 总览 ≈ 40-50k tokens/日。
- L3 深挖版：L2 + 兴趣深挖区（全文抓取 + 六段增强卡 + 背景扩展）≈ 60-80k tokens/日。
- 推荐混合：主体 L2 + 兴趣区 L3；B轨预算 60k → 90k；全文抓取仅兴趣事件 top1-2 篇（~10-20 篇/日，Jina 免费额度）。
- 微信版保持 ≤4KB 不变（门户增强不影响投递纪律）。

### 3.3 版次与新鲜度

- 晨版 08:10（现有 cron）+ 晚版 18:00（新增 cron，同管线 --edition evening）→ 每日两版，页面版次切换。
- hourly 采集 + velocity 继续；静态页不做实时刷新，以「数据截至 HH:MM + 两版」替代 tophub 的订阅流自动刷新。
- 降级纪律沿用：覆盖 ratio<0.70 横幅 + 有界重试（P0-1 已落地）。

## 4. 待用户拍板（5 项设计基调）

1. 骨架：分类门户（总览+分类+兴趣深挖+热榜交叉） vs 保留 TOP10 线性仅加分类 → 推荐前者。
2. 类目划分：8 类（财经/AI与科技/宏观与政策/A股港股/游戏/商品期货/加密/足球，综合并入对应类）
   vs 沿用现有 7 topic → 推荐 8 类（宏观/商品/加密从财经拆出，贴合投资视角）。
3. 知识深度：L2+兴趣L3 混合（~60-80k tokens/日） vs 纯 L2（~45k） vs L1 现状 → 推荐混合。
4. 版次：晨+晚双版 vs 仅晨版 → 推荐双版。
5. 交互：搜索+类目筛选+展开收起+夜间模式（原生 JS 单文件） vs 纯静态 → 推荐前者。

## 5. 实现细节（我定案，可异议）

- 新生成器 portal.py（intel.py brief/publish 调用），数据以 JSON 内嵌单文件，无外部依赖/无构建。
- CSS 移动优先（Android 触控目标 ≥44px），桌面双栏网格；夜间模式 localStorage 记忆。
- 搜索=内嵌标题/实体索引的客户端过滤；类目 tab 锚点 + URL hash 直达。
- 归档页元数据化（每日类目计数/头条），旧 daily 页不动。
- 兴趣区无命中诚实空态；背景段标注纪律；数字核验沿用 synthesize 现有闸。
- 晚版 cron 复用 daily_intel_pipeline.sh（加 edition 参数），告警/降级/留档纪律不变。
- 分阶段交付：P1 骨架+分类区（L2）→ P2 兴趣深挖区（L3）→ P3 热榜交叉+搜索/夜间 → P4 晚版 cron。
  每阶段独立可回滚（portal 生成器开关，回退旧 build_index_html）。
