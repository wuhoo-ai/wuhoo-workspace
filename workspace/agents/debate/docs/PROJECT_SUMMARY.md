## 📊 项目概览

### 项目目标

构建一个基于 TradingAgents 思想的多 Agent 辩论交易系统，通过多空双方辩论 + 独立风控 + 最终决策的分层架构，做出更理性的交易决策。

### 核心思想

模拟真实交易公司的决策流程：
1. **分析师团队**: Bull Agent (多头) vs Bear Agent (空头) 辩论
2. **交易员**: Trader Agent 综合双方观点做决策
3. **风控官**: Risk Agent 独立审核风险
4. **基金经理**: Portfolio Manager 最终审批

## 🔑 关键技术点

### 1. 分层决策架构

```
数据层 → 分析层 → 决策层 → 风控层 → 审批层
```

每层职责明确，相互独立，便于测试和维护。

### 2. 多空辩论机制

- Bull 先输出观点
- Bear 接收 Bull 观点并反驳
- 自动提取共识和分歧点
- Trader 基于辩论结果决策

### 3. 独立风控

- Risk Agent 不受多空影响
- 多维度检查 (止损/仓位/风险收益比)
- 量化风险评分
- 三级审批 (APPROVE/CONDITIONAL/REJECT)

### 4. 数据适配器模式

```python
# 统一接口
adapter.get_data(symbol)

# 内部实现
- QuantaAlphaAdapter
- TrendRadarAdapter
- AkShareAdapter
```

便于扩展新数据源。

### 5. 降级策略

- 数据源不可用时使用模拟数据
- API 超时有重试机制
- 缓存失效时优雅降级

## 📝 经验总结

### 成功经验

1. **分层架构**: 职责清晰，易于维护和测试
2. **适配器模式**: 便于集成新数据源
3. **降级策略**: 提高系统鲁棒性
4. **文档先行**: Prompt 模板先于代码实现
5. **测试驱动**: 边开发边测试

### 踩过的坑

1. **Python 3.6 兼容性**: dataclasses 模块不可用，改用类实现
2. **API 超时**: 需要增加重试和超时处理
3. **文件路径**: 不同环境路径不同，需要自动检测
4. **循环依赖**: adapters 和 agents 之间避免相互引用

### 改进空间

1. **异步支持**: 当前是同步执行，可改为异步提高性能
2. **缓存优化**: 可实现 LRU 缓存，更智能的过期策略
3. **监控告警**: 缺少运行时监控和异常告警
4. **Web 界面**: 当前只有命令行，可增加 Web UI
