## 关键发现

### 1. OpenD curl 检查假阴性
`curl http://127.0.0.1:11111/` 始终超时 — OpenD 使用专有协议非 HTTP。
正确方式: `ss -tlnp | grep 11111`。已更新 SKILL.md。

### 2. Cron 输出缓冲陷阱
Python 在后台进程中 stdout 完全缓冲，14+ 分钟零输出。Agent 只能通过
`/proc/<pid>/io` (rchar/wchar) 和 `VmRSS` 判断进程存活。wchar 从 0 增长到 91MB
但进程结束前一行都不可见。已添加 "Cron Job 输出缓冲陷阱" 章节到 SKILL.md。

### 3. efinance 诊断更新
原文档说 CPU<5% 是卡死信号，但本次 CN 进程 CPU 17% 仍在正常遍历。
已更新诊断标准：区分初期（遍历股票列表，CPU 正常）和后期（卡重试，CPU 低）。

### 4. CN --incremental 预期耗时
Tushare 日线 ~3 分钟 + efinance 换手率 ~7-12 分钟 = 总计 10-15 分钟。
efinance 逐只调用 1000 只中证1000成分股，每 50 只才打印一次进度。
