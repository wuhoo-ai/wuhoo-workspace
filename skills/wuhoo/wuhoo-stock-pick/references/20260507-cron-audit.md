## 监控技术要点

### 通过 rchar 增长率区分 '卡死' vs '慢但活着'

```bash
# 核心方法：多次采样 rchar，计算 KB/s 速率
# 速率稳定 > 100 KB/s → 仍在下载，不是卡死
# 速率降至 0 → 进程卡死（可能 API 超时无响应）

CN_CHILD=$(pgrep -P <bash_pid>)
R1=$(awk '/rchar/ {print $2}' /proc/$CN_CHILD/io)
sleep 60
R2=$(awk '/rchar/ {print $2}' /proc/$CN_CHILD/io)
RATE=$(( (R2 - R1) / 60 / 1024 ))
echo "Download rate: ${RATE} KB/s"
```

### `update_cn_turnover_efinance()` 的内存累积行为

该函数在循环中逐只调用 API，将所有结果 append 到 `all_data` 列表（Python list of DataFrames）。**CSV 文件在整个循环结束后才写入**（`pd.concat()` + 按月分组 + `.to_csv()`）。因此：

- **循环期间**：`turnover_data/` 目录无任何新文件写入 → 这是**正常行为**，不是 bug
- **判断进度**：只能通过 rchar 增长和内存增长（VmRSS/VmData）推断
- **内存占用**：999 只股票 × 550 天历史 ≈ 500MB+ 数据累积在内存中
